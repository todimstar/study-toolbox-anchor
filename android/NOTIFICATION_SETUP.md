# 通知设置指南

## 为什么通知需要进入 App 才能看到？

Android 系统对后台任务有严格限制，尤其是：

### 1. 省电模式和后台限制
- **电池优化**：系统会限制"未优化"应用的后台活动
- **Doze 模式**：设备静置时，系统会延迟后台任务
- **App Standby**：不常用的应用会被限制网络访问

### 2. WorkManager 调度限制
- 最小周期：15 分钟（系统强制）
- 不保证准时：系统会批量执行以省电
- 网络要求：需要联网才会触发

### 3. 桌面红点（Badge）支持
- **依赖启动器**：只有支持通知点的启动器（如 MIUI、EMUI、OneUI）才会显示
- **需要权限**：通知渠道必须启用"桌面角标"
- **系统差异**：不同厂商实现不同

---

## 用户需要手动配置的设置

### ✅ 必做：关闭电池优化
1. 打开 **设置 > 应用 > 学习工具箱**
2. 找到 **电池优化** 或 **电池使用**
3. 选择 **不限制** 或 **允许后台活动**

### ✅ 必做：允许通知权限
1. 打开 **设置 > 应用 > 学习工具箱 > 通知**
2. 确保 **允许通知** 开关打开
3. 确保 **微聊新消息** 渠道已启用
4. 确保 **桌面角标** 或 **通知点** 已启用

### ✅ 推荐：自启动权限（部分厂商）
- **小米 MIUI**：设置 > 应用设置 > 应用管理 > 学习工具箱 > 自启动
- **华为 EMUI**：设置 > 应用 > 应用启动管理 > 学习工具箱 > 手动管理 > 允许自启动
- **OPPO ColorOS**：设置 > 应用管理 > 学习工具箱 > 权限 > 自启动

## 当前实现的通知机制

### 1. WorkManager 后台轮询
- **周期**：每 15 分钟
- **触发条件**：有网络连接
- **行为**：
  - 获取最新 20 条消息
  - 找到最新的家长消息
  - 如果有新消息且未通知过，发送通知

### 2. WebView 内轮询（App 打开时）
- **周期**：每 3 秒
- **触发条件**：微聊页面活跃
- **行为**：
  - 实时显示新消息
  - 调用 JSBridge 发送系统通知

### 3. 通知去重
- 使用 `SharedPreferences` 记录最后通知的消息 ID
- 避免重复通知同一条消息

---

## 已知限制

1. **不是实时推送**：最快 15 分钟才会检查一次（WorkManager 限制）
2. **不保证准时**：系统可能延迟到 30 分钟甚至更久
3. **桌面红点不一定显示**：取决于启动器支持
4. **省电模式下可能失效**：系统会进一步限制后台任务

---

## 替代方案（未来可考虑）

### 方案 1：前台服务（更可靠，但耗电）
- 显示常驻通知
- 可以保持长期后台运行
- 用户体验不佳（通知栏常驻）

### 方案 2：推送服务（需要服务端支持）
- FCM / 极光推送 / 个推
- 实时性好
- 需要额外的服务端配置和维护

### 方案 3：缩短轮询周期（不推荐）
- WorkManager 最低 15 分钟
- 可以用 AlarmManager，但会被系统限制
- 耗电量增加

## 测试建议

### 手动触发测试
```bash
# ADB 触发 WorkManager 任务
adb shell am broadcast -a androidx.work.diagnostics.REQUEST_DIAGNOSTICS
```

### 查看 WorkManager 状态
```bash
adb shell dumpsys jobscheduler | grep study_toolbox
```

### 查看通知权限
```bash
adb shell dumpsys notification | grep study
```
